# Hydroponics air stone controller

ESPHome firmware for a USB-confirmed ESP32-C6FH4 (4 MB flash), one 18650 cell,
an INA219 measuring the total battery load, and an active-high GPIO18 MOSFET
pump switch. The controller stays awake on Wi-Fi for live Home Assistant
control and telemetry. Based on the neighboring Tower Controller's ESP-IDF,
encrypted native API, and pump-off boot conventions; this project does not
inherit its deep-sleep cycle. At the owner's request, the internal brownout
detector is disabled for this module after repeat startup resets. The INA219
software battery cutoff remains enabled; external cell/BMS protection is still
required. This setting does not correct a weak power supply.

See [COMMISSIONING.md](COMMISSIONING.md) for observed installation results and
the successful GPIO6/GPIO7 scan and remaining supply/current-direction checks.

## First use

Local `secrets.yaml` already contains the Tower Controller's Wi-Fi credentials
and a newly generated device API key. It is excluded from Git. New checkouts:
copy `secrets.example.yaml` to `secrets.yaml`, fill in Wi-Fi, and generate a key
with `openssl rand -base64 32`. Never commit the real secrets file.

Use ESPHome 2026.9.1 (`pip install -r requirements.txt` in a virtual environment):

```sh
./scripts/check.sh
esphome compile air-stone-controller.yaml
esphome upload air-stone-controller.yaml --device /dev/tty.usbmodem1101
esphome logs air-stone-controller.yaml --device /dev/tty.usbmodem1101
```

The first installation has **Automatic Schedule OFF** and GPIO18 LOW. Check
the boot log for INA219 at `0x40`, plausible cell voltage, and positive current
with the pump disconnected. Check the gate output before connecting the pump.
Then use a five-second run to commission the pump while watching battery
voltage, current, MOSFET temperature, and actual pump operation.

Build output lives in `/private/tmp/air-stone-controller-build`, because the
workspace path contains spaces. It is disposable and excluded from Git.
Subsequent uploads can use `--device air-stone-controller.local` or its IP.
OTA is encrypted and authenticated with the same API key.

## Home Assistant

1. In **Settings → Devices & services**, accept the discovered ESPHome device;
   otherwise add the ESPHome integration with `air-stone-controller.local`
   (or its IP), port 6053.
2. When asked for the encryption key, copy `api_encryption_key` from local
   `secrets.yaml`. The device has its own key, distinct from the Tower.
3. On the device page, set **Pump Run Time** (seconds) and **Pump Rest Time**
   (minutes), then enable **Automatic Schedule**. Defaults are 60 seconds ON,
   then 15 minutes OFF, giving roughly 16 minutes between starts. These are
   initial commissioning values, not a validated oxygenation regime.
4. Add the cards in `home-assistant-dashboard.yaml` to a manual dashboard card.
   Match their example entity IDs to those generated by your installation.

Enabling the schedule requests a run once battery measurements are valid. The
cycle runs on the ESP32 even without Home Assistant or Wi-Fi. Rest is measured
from the end of the preceding run; the voltage measurement adds about three
seconds after the rest interval. Run duration is captured at each start;
edits apply to the next run. Rest edits affect the current wait. Disabling the
schedule immediately stops the pump. **Stop Pump** / switching **Pump** off
stops the current run and begins a new rest; disable the schedule to keep it
stopped. **Run Pump Once** / switching **Pump** on requests one timed run,
even with the schedule disabled. Repeated ON commands cannot extend a run.

Run/rest and schedule settings persist after the five-minute preference flush.
On a later reboot, GPIO18 first goes LOW; a previously saved enabled schedule
can then start a new full run after valid measurements. Manual runs, elapsed
cycle phase, and safety-trip latches do not persist through a reboot.

Battery Voltage, Battery Current (A), Battery Power (W), and Discharge Power (W)
have measurement metadata for Home Assistant statistics. **Energy Used** is a
restored discharge-only integral in Wh. Leave these entities included in HA's
Recorder for history and long-term statistics; raw-history retention is set
in Home Assistant. HA records only samples received while connected. The
on-device energy counter continues offline, with saved totals up to five
minutes behind after abrupt power loss. During INA219 outages the energy
integral is paused after a five-second stale timeout, so gaps undercount real
usage; the timeout can still integrate up to five seconds of the last value.

## Physical button and USB-A test

Connect the normally-open tactile switch between GPIO0 and GND. The input is
active low with an internal pull-up and 40 ms debounce. One press requests a
timed run using Pump Run Time (60 seconds by default); another press stops it.
Holding the button does not repeat. It works without Home Assistant and uses
the same INA219 checks, battery cutoff and maximum run time as other controls.
It is ignored during OTA. A stop begins a new rest period if the automatic
schedule is enabled; disable the schedule to keep the pump stopped.

For a USB-A output test, leave Automatic Schedule OFF, connect the intended
pump/load and press the button. Confirm the load actually operates, measure
USB-A VBUS to USB-A GND for about 5 V under load, and press again to stop.
Firmware can confirm GPIO18 was commanded HIGH and show battery-side power;
it cannot directly measure the USB-A output voltage. Whether USB-A itself
switches depends on whether GPIO18 gates the boost input or only the pump.
Do not connect the boost USB-A output to the computer as a test load.

## Battery voltage under pump load

Before each scheduled or manual run, the controller keeps the pump off for
at least three seconds and averages at least three new INA219 voltage samples.
**Pump Status** shows *Measuring resting battery voltage* while it waits.
**Stop Pump** or a second physical button press cancels the pending run.

**Pre-Pump Battery Voltage** is the resting average for the latest run.
**Minimum Pump Battery Voltage** is the lowest sample measured while the
pump output is active, and **Pump Voltage Sag** is the drop from the resting
average to that minimum, floored at zero. The loaded values start as
unavailable until the first loaded sample and stay visible after the run.
They reset for the next run and are not restored across reboot. At the 1 Hz
sample rate, this measures sustained sag and can miss a brief startup dip.
For a battery-only comparison, disconnect USB power from the ESP32.

## Wiring and measurement

| Connection | Pin / route |
| --- | --- |
| INA219 SDA | GPIO6 |
| INA219 SCL | GPIO7 |
| INA219 VCC | ESP32 3V3 (I2C pull-ups must also be 3.3 V) |
| INA219 GND | Common battery / ESP32 ground |
| INA219 VIN+ | Protected battery positive |
| INA219 VIN- | Positive supply feeding **both** ESP32 regulator and boost |
| MOSFET gate control | GPIO18, HIGH = on |
| Tactile pump button | GPIO0 to GND, normally open; internal pull-up |

The VIN- load bus voltage plus the signed shunt drop gives battery-side VIN+
voltage. Battery Power is that voltage multiplied by signed current; positive
means discharge for the orientation above. This includes ESP32 consumption,
converter loss, pump and any USB-A loads downstream of the shunt. USB power to
the ESP32 can supply some load without crossing the shunt, so USB-connected
readings do not establish battery-only consumption. A single INA219 cannot
isolate pump-only power or establish remaining battery capacity. No battery
percentage/runtime estimate is presented without cell characterization.

The current model assumes a typical **R100 / 0.1-ohm** shunt, 3.2 A measurement
range, default address `0x40`, and a 1S cell voltage range. Verify the shunt:
wrong resistance directly scales current/power. The software current limit
is **2.5 A total battery current**, not a board rating or an instantaneous
short-circuit protection. Verify the actual shunt wattage and lower the limit
if necessary; at 2.5 A a 0.1-ohm shunt dissipates 0.625 W.

For a bare IRLZ44N used as a low-side **pump** switch, wire boost 5V to pump +,
pump - to drain, source to common ground, and GPIO18 to gate through roughly
100–220 ohms. Add a 10 kohm gate-to-source pulldown so reset cannot float the
gate. Fit an appropriately rated flyback diode across a brushed DC pump
(cathode to +5V, anode to the switched pump negative). Confirm the pump type
and any built-in suppression. The TO-220 tab is electrically drain.

If your MOSFET instead switches the boost converter's negative input, its
switched ground must not be bridged back to common ground through USB-A,
programming cables, or other wiring. The exact MOSFET position has not yet
been confirmed. The firmware assumes only an active-high gate; check that
LOW actually removes pump power. An idle boost can consume battery even when
a downstream pump switch is off. Avoid connecting a second powered USB source
to the boost output unless the module explicitly supports it.

IRLZ44N on-resistance is specified at 4 V and 10 V gate drive, not 3.3 V;
logic-level labeling alone does not establish low loss from an ESP32. Verify
voltage drop/heating at pump startup and running load, or use a switch with
on-resistance specified at 2.5/3.3 V or a suitable driver. Use a protected 1S
cell/BMS, a fuse suited to wiring/load, and a regulator intended for an ESP32;
do not connect a full 4.2 V cell directly to 3V3.

SDA/SCL use GPIO6/GPIO7 after moving the connectors from GPIO4/GPIO5.
GPIO6/GPIO7 are not strapping pins. They share external JTAG functions, so
do not attach an external JTAG probe to these pins while using I2C; USB
Serial/JTAG on GPIO12/GPIO13 remains available.

## Pump protections

- Output forced off at GPIO setup, boot, shutdown and OTA update.
- Starts require a complete INA219 sample less than five seconds old, finite
  readings, cell voltage **3.30–4.35 V**, and absolute current below 2.5 A.
- While running, an unsafe reading or stale sensor stops the pump and latches
  **Safety Trip** until **Clear Safety Trip** is pressed with a fresh healthy
  sample and battery voltage at least **3.60 V** (or the controller reboots).
- Requests received while inhibited/tripped are discarded. No delayed manual
  start occurs after recovery. Automatic mode may start after inhibition
  clears if no running safety trip occurred.
- Every run, including manual runs, has a 30-minute maximum. The 250 ms
  scheduler checks elapsed monotonic time; a one-second INA219 sample interval
  plus polling is not fast hardware overcurrent protection. A frozen CPU or
  stuck MOSFET needs hardware protection.

This awake-Wi-Fi design trades battery life for responsive control. Measure
actual idle and run consumption before judging 18650 runtime. Battery state,
pump schedule, and aeration needs should guide any later low-power version.

## Validation and references

`./scripts/check.sh` runs host C++ tests of the same scheduler used in firmware:
duty/rest boundaries, manual operation, low battery, stale/missing/invalid
sensor data, signed overcurrent, fault recovery, duration edits, maximum run,
and 32-bit timer rollover. It also validates the ESPHome YAML. Compile with the
pinned ESPHome version before uploading.
